## LinkedIn — the engineering boundary

The useful moment in our SilentShift demonstration is a model error. It proposed ALLOW for an unsupported unit change. The deterministic policy held the case instead.

A separate approved-amendment case delivered once. Both records retain the message, evidence, proposal, policy and signed receipt. The distinction matters: a working demonstration is not proof of general accuracy, and a signature proves integrity rather than business correctness.

SilentShift is an open-source IRIS AI Hub interoperability workflow, demonstrated with synthetic orders and a destination simulator. Native release 0.3.2 includes the Java PEX exporter; the workbench is built separately.

Project and installation: https://github.com/himanshu748/silentshift

## X / LinkedIn — inspect the receipt

A signed receipt has three separate questions: do the bytes match, is the signing key the expected one, and was the business decision correct?

SilentShift's local receipt inspector makes the first two inspectable using a real synthetic Java PEX export. It does not authorize a transaction or certify the underlying evidence.

Code and scope: https://github.com/himanshu748/silentshift
