# Competitive review — November 3, 2026

**Historical research snapshot.** The eight-entry comparison below records November 3 observations and has not been rerun against every current competitor. On November 4, contest 49 lists 15 entries including SilentShift. The public repository, demo, two articles, native tracing, Workflow, vectors, adapter and IPM are now delivered; the current [submission checklist](SUBMISSION_CHECKLIST.md) supersedes this document's original handoff priorities. No new competitor ranking is implied.

The [contest list](https://openexchange.intersystems.com/contest/49) displayed eight registered applications, all showing “0 Bonuses.” That display is not an audited eligibility score. This review does not rank winners or claim that SilentShift is best or unique. Judging covers Complexity, Clarity of Instructions, Developer Experience, Applicability and Usability; no numerical weights are published there.

Evidence labels: **R** = public README/OEX material read; capabilities and reported results remain author claims. **C** = selected implementation files statically inspected, corroborating the named mechanism. **Executed** = independently run by this project team; **none of these competitors were executed**. Videos were linked, not watched. Hosted demo availability, clean installation, test results and bonus awards were not independently verified. This is selective product research, not a security or complete code audit.

## SilentShift's strongest defensible demonstration

Lead with **pre-delivery contract semantics**: the integration accepts a structurally valid event, but its business meaning contradicts a separately selected approved record. The A/C pair is the clearest proof: a unit change is held without authorization and allowed when an effective approved amendment supports it. Then show conflicting authorities going to review and a hostile recommendation failing policy. These are synthetic, locally governed reference snapshots, not live supplier/ERP or bank integrations.

The current project has observed native five-scenario outcomes, an empty-state fresh installation followed by a successful clean-install run, and a real browser Scenario Lab C delivery. Proof is in [BUILD_STATUS.md](BUILD_STATUS.md), `evidence/native/clean-install-initial.json`, `evidence/native/clean-install.json` (run `0503b649-ee6f-495e-be37-166db508377c`) and `evidence/browser/browser-scenario-delivered.png`. Do not repeat earlier claims that these gates remain blocked.

Retain the earlier run where the model proposed 4/5 correct outcomes and policy delivered 5/5; it explains why policy matters. The later clean run returned 5/5 proposals/final outcomes. The rule-only baseline also solves all five frozen examples: **no AI accuracy uplift or general business accuracy is established**. Show evidence retrieval, uncertainty, inspectable reasoning and policy constraints without implying that these tiny samples prove superior models or real-world reliability.
