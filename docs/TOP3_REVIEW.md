# Voting-week product review

Reviewed November 9, 2026 against the [official contest](https://openexchange.intersystems.com/contest/49) and [expert preparation advice](https://community.intersystems.com/post/what-experts-look-contest-entries). The public contest displayed 43 entries. No score, placing or probability of winning is inferred.

## The strongest defensible story

An integration operator receives a technically valid order whose unit of commitment changed. SilentShift makes the incoming value, independently approved reference, investigation and resulting hold visible in one native workflow. An effective approved amendment changes the demonstrated outcome. Reviewers resolve eligible holds without bypassing critical contradictions.

Lead with that operator task. Native AI Hub, provider-call tracing, Workflow, vectors and the file adapter explain the mechanism; a feature inventory should not replace the story. CSV is a practical intake path, but the supplied data remains synthetic and delivery simulator-only.

The held-out comparison is a tradeoff, not an accuracy victory. Agent + policy produced fewer wrong simulator deliveries than the baseline's counterfactual release choices, but did not improve overall correct routing or the unstructured split. Prose authority and structured-policy disagreement remain product limitations. [Full comparison](EVAL_HELDOUT.md).

## Criteria and evidence

| Criterion | What a judge can inspect | Remaining limit |
| --- | --- | --- |
| Complexity | Native Service → Process → AI Hub/tools → policy → routing; per-call Visual Trace; Workflow; native-vector and adapter receipts in [the feature guide](FEATURES.md) | No claim that these mechanisms are unique or outperform competing entries |
| Clarity of instructions | One [installation guide](../INSTALL.md), then the short README journey | Licensed build 154 must already be obtainable; the repository cannot redistribute it |
| Developer experience | [Fresh source quality gate](evidence/top3-quality.json): native suite, both keyless replays, fresh local inference and actual frontend reads | Public IPM remains 0.3.0; new provider configuration is a source-branch change. External services are unverified |
| Applicability | Independent order/reference CSV sources, bounded preview/import, original records and explicit authority | Synthetic data only; no external ERP/bank integration, X12 parser or whole-order completeness guarantee |
| Usability | [Multi-page receipt](evidence/top3-multipage.json): direct document loads, responsive layouts, keyboard/reduced motion, native CSV workflow and critical review veto | A local setup is still required until hosting is verified |

The advice favours an accessible demo, a clear README and evidence of difficult engineering decisions. It is guidance, not another weighted rubric. A hosted URL alone would not establish a working live demo; inference, viewer restrictions, reset, limits and teardown must also be exercised.

## Competitive positioning

The [Interop Triage listing](https://openexchange.intersystems.com/package/Interop-Triage) targets failed production messages. [Proof Before Pay](https://openexchange.intersystems.com/package/Proof-Before-Pay) describes sealed evidence and controlled synthetic payment effects. [IRIS Chronos](https://openexchange.intersystems.com/package/IRIS-Chronos) targets shipment recovery. These are public descriptions, not applications independently executed here.

Evidence, policy boundaries and native tracing are not enough to claim novelty on their own. SilentShift should make its order-meaning problem immediately clear and show its own working path thoroughly. Their evaluations and ours use different cases; comparing those headline scores would not establish a ranking.
