# Frontend remake brief

For integration operations teams, the important question is whether a technically accepted order matches the business agreement. SilentShift should make that question easy to understand before asking someone to inspect a trace or configure a model.

## Direction

Keep the Signal / Substance visual identity: ink surfaces, mint actions, warm semantic status colors, Manrope and readable monospaced values. Make the composition more deliberate through scale, spacing and a strong evidence comparison. Avoid another row of generic feature cards, invented metrics or a decorative dashboard. Motion should explain an action or a returned result, with no ambient loops and full reduced-motion support.

The landing page should make the `20 CASE` versus `240 EA` moment the main product explanation. Lead with the successful-request/wrong-business-meaning problem, the integration-team audience and the consequence of holding the order. Keep the interactive comparison clearly labeled as a synthetic illustration that makes no API/model call. Use the real Scenario Lab and workbench as the next steps. Give native IRIS, human review and Visual Trace a clear place deeper in the story. Screenshots remain labeled recorded captures.

The workbench should help a first-time operator get connected and start a meaningful task. Its current unauthenticated view repeats the same technical error in the queue and main pane. Replace that visual dead end with one clear connection explanation and action, while preserving the real permission state. A permission refusal must remain distinct from an unavailable runtime. Never fill an empty queue with invented records.

For a connected investigation, prioritize the contradiction, the approved reference, the observed route and the next permitted action. Keep original payloads, agent recommendations, policy checks, review receipts and trace links accessible without letting IDs and implementation details dominate the main reading order. The AI recommendation and the final policy remain visually distinct.

## Boundaries

- Frontend files only. Preserve API paths, strict schemas, event/case identity, authentication, role checks and all backend behavior.
- Preserve Scenario Lab, investigation search/filters, review safeguards, CSV preview/commit, command navigation and keyboard behavior.
- Keep synthetic-data, simulator-delivery, recorded-capture and unavailable-runtime explanations. No hosted demo, accuracy uplift, ranking or award claim.
- The held-out run is incomplete. Do not use it in landing copy or change its inputs, labels or results. README/listing wording is outside this remake.
- Use existing React, TypeScript, CSS, local fonts and icons. Add no paid assets, new service, tracking, generation provider or dependency without a concrete need and approval.
- Work on `push/top3`; do not push main, publish a package, edit OEX or upload anything.

## CoCo execution

Use the owner's existing free CoCo entitlement. The official CLI is installed; connection setup is pending browser sign-in. Code mode disables Snowflake data tools; cloud mode will remain off. No warehouse, database, model hosting or new subscription is needed for this design work.

Provide CoCo only the public frontend source, its relevant contracts and this brief in a separate workspace. Exclude `.env`, credentials, private logs, native runtime assets and unpublished raw evidence. Start with a bounded design/code draft, review its diff, then integrate and test it here. A CoCo completion message is not browser verification.

## Acceptance

The implemented result must pass TypeScript/build and the applicable existing browser checks. Inspect the rendered landing and workbench at desktop and mobile sizes; verify focus order, connection dialogs, command navigation, error recovery and reduced motion. Exercise connected views against actual native records where access permits. Record what was run and distinguish disconnected UI checks from live model execution. No native five-case rerun is implied by frontend-only checks.
