# Frontend rebuild brief

SilentShift helps integration operations teams catch orders and payments that are technically valid but contradict the business agreement before delivery. An order saying 20 CASE can conflict with a contract for 240 EA; an effective approved amendment can authorize it. Native InterSystems IRIS AI Hub investigates evidence; deterministic policy decides the route; human reviewers handle eligible holds. The workbench includes an investigation queue and case evidence, review tasks, bounded CSV order import, synthetic Scenario Lab, message traces and system status.

Build the frontend from scratch and wire it to the existing native backend. Choose the visual direction yourself. The supplied frontend is a reference for functionality and integration, not a design to preserve. Use web/src/api.ts and schema.ts as the real API/authentication contracts; preserve their public behavior. Keep all existing capabilities working, including CSV preview/commit, case and trace links, reason-required review safeguards, keyboard navigation, responsive use and reduced motion. Retain honest synthetic-example and simulator-delivery labels; don't invent records, metrics, hosted-demo or benchmark results.

Implement the frontend now, rather than returning a plan. You may rewrite the frontend components and styles under web/src, keeping TypeScript/React and the existing installed dependencies. API and schema contracts, backend/runtime, README, evidence, fixtures and dependencies are outside the edit scope. Read only the files supplied in this workspace. No shell, SQL, web, cloud, agents, credentials, publishing or external actions. You have read/write/edit/search tools for this isolated frontend copy only. The owner will integrate and run tests after reviewing your files.

The owner explicitly requested that CoCo choose the design rather than follow a prescribed palette or layout. Generation runs in a separate frontend copy with the existing account entitlement; cloud mode and Snowflake compute stay off.
