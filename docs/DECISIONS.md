# Decisions and limits

| Decision | Reason / evidence | Revisit when |
|---|---|---|
| Keep SilentShift and the semantic-integrity workflow | User-selected product; official entries reinforce the need to distinguish from generic anomaly triage | Evidence disproves its central workflow |
| IRIS owns the full processing journey | Mandatory contest interoperability and native AI Hub requirements | Never substitute an outside-IRIS demo pipeline |
| Small pure Python engine called through Embedded Python | Exact decimal arithmetic and reusable property tests without a second service | Measured performance requires another approach |
| Read-only case-scoped native tools | Retrieved text cannot authorize mutations; agent recommendation stays independent of routing | New evidence source has a validated need |
| Native source before interface; offline UI stays empty | Runtime kit currently unavailable; no invented operational history | Real persisted cases exist |
| Five frozen synthetic cases with a checksum | Reproducible expected outcomes and honest denominators | New dataset version has independently justified labels |
| Report baseline strength | The rule-only baseline solves all five initial examples; this dataset provides no evidence of AI accuracy improvement | A representative measured evaluation shows useful investigation gains |
| Local or authorized existing model only | No provider key, paid budget or cloud entitlement established | User supplies access and bounds |
| Docker cloud left aside | Installed CLI has no Offload/remote context; user said “let it be” and is freeing disk space | User provides an existing host/entitlement |
| No optional bonus infrastructure yet | Native P0 proof and submission readiness take precedence | Mandatory gates pass |
| No submission success claim | No public repo/OEX/contest receipt observed | Actual separate confirmations are retained |

Official source/API pins and remaining SDK uncertainties are in `NATIVE_AI_HUB.md`; rules and deadline in `CONTEST_COMPLIANCE.md`.
